# One-time Kodus setup

The `code-reviewer` agent shells out to the [Kodus CLI](https://github.com/kodustech/cli)
(`kodus review`) against a **self-hosted Kodus** instance. Kodus is a full stack
(web, API, workers, webhooks, MCP manager, RabbitMQ, Postgres/pgvector, Mongo).

Until it is configured, the `code-reviewer` agent still runs — it just returns a
single informational finding ("KODUS_TEAM_KEY not set") and the pipeline
completes without a Kodus review.

## Quick start

```bash
make kodus-up
```

That is the whole setup. `make kodus-up`:

1. clones `github.com/kodustech/kodus-installer` into `.kodus/`, copies
   `.env.example` to `.kodus/.env`, generates secrets, and pre-fills the LLM
   lines (see below);
2. runs the installer's `docker compose up -d` (API on
   `http://localhost:3001`, web UI on `http://localhost:3000`);
3. runs `make kodus-bootstrap`, which creates the first org/user, injects your
   Anthropic key as a BYOK provider, mints a team key, and writes
   `KODUS_TEAM_KEY` + `KODUS_API_URL` into this repo's `.env` — **no web login
   page**.

Then `make up` (or restarting `agent-code-reviewer`) picks up the key.

## What the headless bootstrap does

`scripts/kodus-bootstrap.sh` drives the Kodus REST API directly:

| Step | Endpoint |
|---|---|
| First user + org + team (role OWNER) | `POST /auth/signUp` |
| JWT | `POST /auth/login` |
| Team id | `GET /team/` |
| Inject `ANTHROPIC_API_KEY` as BYOK provider `anthropic` | `POST /organization-parameters/create-or-update` |
| Mint the CLI team key | `POST /teams/{teamId}/cli-keys` |

The generated account credentials are stored in `.kodus/bootstrap.json`
(git-ignored, `chmod 600`) so re-runs reuse the account and just rotate the key.
Run it again any time with:

```bash
make kodus-bootstrap
```

If you want to browse reviews in the web UI, log in at `http://localhost:3000`
with the email/password from `.kodus/bootstrap.json`.

## LLM configuration

`make kodus-up` pre-fills `.kodus/.env` so Kodus can reach Claude even before the
BYOK step, using Anthropic's OpenAI-compatible endpoint:

```
API_OPEN_AI_API_KEY=<your ANTHROPIC_API_KEY>
API_OPENAI_FORCE_BASE_URL=https://api.anthropic.com/v1/
API_LLM_PROVIDER_MODEL=claude-sonnet-5
```

`make kodus-bootstrap` then also saves the key as a proper **BYOK provider** on
the org (native `anthropic`, model `claude-sonnet-5`, falling back to a dated
Claude id if the catalog rejects it). After that the env keys above are just a
fallback — `GET /organization-parameters/llm-config/status` reports `byok` as the
active source.

`.kodus/.env` is generated by the installer — **do not hand-edit it.** In
particular `API_NODE_ENV` must stay `production` for self-hosted (its own comment
block explains why: `development`/`test` emit the SSO handoff cookie without the
`Secure`/`Domain` attributes). There is no "disable auth" flag in Kodus; the
bootstrap script is the supported way to skip the login page.

## Known rough edges

- **HTTPS check:** the Kodus CLI wants HTTPS for a non-`localhost`
  `KODUS_API_URL`. `http://host.docker.internal:3001` may be rejected. If so:
  run the code-reviewer on the host instead of in a container (it then uses
  `http://localhost:3001`), or put a TLS-terminating proxy in front of
  `kodus-api`.
- **Version drift:** `kodus-installer`'s compose and `.env` schema change over
  time. If `make kodus-up` fails, follow the installer's own README in `.kodus/`.
  If the bootstrap script's endpoints 404, check the API's OpenAPI at
  `http://localhost:3001/docs` (set `API_DOCS_ENABLED=true` in `.kodus/.env`).
